## 逐批持久化与复现边界

恢复编排位于 `recovery_20261021_v1/recover.py`，通过原冻结的 `accelerated_prefixes` 执行数值计算，使用原有模型、噪声身份、采样序列、B64/G1、尾批、FP64 在线均值、重建及 metrics。未修改 manifest 绑定的 245 项执行源码/协议文件。

新增采样 sweep 将每个原始 B64/尾批的 N 前缀均值保存为独立 NPZ，包含原始 chunk 索引；写入、flush/fsync 后，以原子提交的 JSON 保存文件 SHA256、批次区间及固定合同身份。缓存目录位于 `<sampler>_sampling/batch_cache/`。以后恢复可以通过 `--resume-run` 在新输出目录读取已提交批次；未提交的批次文件保留并明确记录后重新计算，损坏、错序或合同不同的缓存显式失败。

CPU synthetic 定向测试 **3 项通过**，分别验证 DDIM、DDPM 在两批提交后中断并恢复，与原冻结采样结果逐值相同；仅计算剩余批次，尾批正确，模型状态不变。缓存篡改、错误身份和缺少 CLI 授权均被拒绝。旧 GPU 验收保持复用，未重跑已完成的六项历史验收。

缓存中累计的逐批前缀耗时代表各批首次计算的时间，不包含持久化写盘，也不等于恢复任务墙钟。各配置的独立 B64 计时仍在本阶段结束前按原合同执行。
